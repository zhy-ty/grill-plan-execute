# Execution Contract 模板（执行期义务的唯一语义源）

本文件是**本仓库自有产物的版式**，不含任何上游正文。

计划头部放**完整实例化**的合约正文，每个 Task 末尾放**本任务适用的义务短句**。两处都由本模板生成，语义只在这里定义一次：改义务改本文件，已发出的计划作为快照不回改。**不要**在环境文档或发现台账末尾再抄一份这些义务——那会开出第五处副本。

## 实例化规则

1. 把所有 `<...>` 占位符换成本里程碑的实际值。占位符填不出来就是显式缺口，按 `needs-input`／`blocked` 处理，不许留空或凭默认答案填。
2. 计划头部放下面「合约正文」全文。
3. 每个 Task 末尾放 3–5 行短句：全局义务（E1 的一部分、E2、E5）每个 Task 都要有；任务特有义务按实际触发列。
4. **禁止编号引用**——不许写"见计划头部 E3"这类指向。任务级上下文未必包含计划头部，指向它读不到的地方比重复更糟。宁可重复短句。
5. 整份合约不在 Task 里重复；重复的只是同一实例的短句。

## 合约正文（原样实例化后放进计划头部）

```
## Execution Contract — <topic> / <里程碑 Mk>

本计划是执行会话唯一的交接入口；执行会话不加载任何编排 skill，以下义务对本里程碑全程有效，与你的默认习惯冲突时以本节为准。

E1 开工前必读：环境文档 <绝对路径>；发现台账 <绝对路径> 中本里程碑相关条目 + 全部标"坑"的条目。
   文件里已记录的事实（路径、地址、服务状态、凭据用途）自己读取或按记录的探测命令实测，不得转成用户问题。
E2 纠正当场记账：用户纠正了你，或实测证伪了既有认知（假通过的验证脚本、误判的可达性、过时的契约表述），
   当场往发现台账追加一行，不许攒到收尾，也不许只改代码不记账。
E3 提问前先查：准备问用户之前，先查本计划 Key Decisions、locked 决策索引 <路径>、Workflow Resume、发现台账。
   命中已有结论就引用它继续；只有新证据与原结论冲突时才升级，并附冲突证据与出处。
E4 可达性不许猜：本计划 Code Facts 已标每条"谁在用"与三态（活跃／仅历史兼容／废弃不改）。
   动手改落在后两态的代码之前，按 E1 取到的证据重新确认一次。
E5 完成要有证据：每个 Task 做完就在计划文档对应条目打勾。没有当场跑过测试/构建并读到输出，
   不许声称完成；拿不到证据就写 blocked。
E6 收尾写 close-out：本里程碑结束时写 <计划同目录>/<计划名>-close-out.md，必含三行——
   「本里程碑发现：无」或发现清单、验证证据（命令+输出摘要+证据路径）、Task 完成度 x/y。
   "无／不确定／blocked"都是合法值：不许为好看编内容，也不许为了填满清单编造发现。
E7 暂停留锚点：任何暂停或阻塞前，把已有草稿路径与待解问题写进 close-out 或计划文档，
   恢复时从草稿续写，不从头重写。
```

## 每 Task 末尾的短句版式

```
本任务适用：
- 被用户纠正或实测证伪时，当场往发现台账追加一行（<台账绝对路径>）
- 完成即勾选本 Task；没有当场跑出的验证证据不得声称完成
- <任务特有义务，例：改 <文件:符号> 前先重确认它的可达性三态结论>
- <任务特有义务，例：本任务涉及登录态／凭据，用途与来源见环境文档 <条目号>>
```

触发义务超过 5 条时，写成"本任务另适用：〈短句〉〈短句〉"，仍然不用编号引用。
